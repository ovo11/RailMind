# RailMind RAG 检索效果评测报告

**比赛项目：** RailMind 列车智能运维智能体平台  
**分工模块：** RAG 检索效果评测  
**评测日期：** 2026 年 9 月 22 日  
**评测版本：** `e5bd01d8b76a23cc17b9a54de2cb2641298792fb`  
**评测性质：** 内置演示知识库上的离线检索复测与指标复核

## 一、评测背景与目标

RailMind 面向列车运维场景，将复合材料结构、受电弓、车底检查门、线路侧及车厢巡检等能力接入智能体平台。RAG 模块为诊断解释和处置建议提供知识依据，其检索结果是否相关、排序是否合理、知识不足时是否拒绝返回依据，会直接影响后续回答和工单引用。[1][2]

本次工作聚焦检索环节：复跑仓库已有评测，独立核对指标，补充关键词路径失败分析及参数敏感性实验，形成可追溯的结果记录。未将检索命中率解释为最终回答准确率，也未将已有开发工作归为本次新增成果。

主要评测问题：

1. 前 3 条结果能否命中预先标注的相关知识章节？
2. 自然语言查询与关键词查询的效果有何差异？
3. 无相关知识或领域不匹配时，系统是否拒绝返回依据？
4. 原报告的指标口径、失败统计和技术描述是否与代码一致？

## 二、评测对象与实际实现

### 2.1 检索流程

当前链路为：资产类型及状态过滤 → 领域词表查询扩展 → 字符 TF-IDF 相似度计算 → 关键词分支计分 → 加权及相似度门槛过滤 → 排序返回 Top-K → 输出引用元数据。[2]

| 项目 | 代码核实结果 |
| --- | --- |
| 索引 | scikit-learn `TfidfVectorizer`，字符 1～4 gram，子线性 TF，最多 12,000 个特征 |
| 相似度 | TF-IDF 向量余弦相似度；不是深度 Embedding 模型 |
| 自然语言分支 | `_bm25_scores()` 实际计算同一 TF-IDF 向量点积并按最大值归一化，不是标准 BM25 |
| 显式关键词分支 | 字符串出现次数，标题额外加 2、章节额外加 1，最后归一化；IDF 加权未实际执行 |
| 默认参数 | Top-K=3，α=0.55 |
| 返回过滤门槛 | 自然语言分支通常为 0.06；关键词分支有匹配时为 0.08；关键词得分全零时为 0.15 |
| 输出依据 | 文档 ID、标题、章节、页码、版本、状态、引文与标签 |
| 重排序 | 加权分数排序；未使用独立重排序模型 |

因此，本报告采用“字符 TF-IDF 与关键词加权检索”描述当前实现，不将其写成“深度语义向量、标准 BM25 与 Reranker 组成的完整检索链路”。

### 2.2 两条评测路径与实际接入

- `search()`：输入原始自然语言问题及预先指定的资产领域。
- `retrieve()`：输入预先给定的关键词列表及资产领域，原问题全文不传入检索器。

代码核查显示，Chief、专业 Agent 以及 ChatAgent 的 `kb_search` 工具均调用 `retrieve()`。因此不能把 `search()` 的高分直接当作对话助手或完整 Agent 链路的实际效果。关键词评测也只验证给定关键词下的检索，不包含 LLM 选择工具、抽取关键词或判断领域的准确率。[5][6]

按 `(document_id, chapter)` 去重后，共 **22 个唯一章节标识**；其中通用告警升级章节在 5 个领域各存一份。评测标注覆盖全部 22 个章节标识，但不能据此宣称覆盖了每个领域副本、全部业务条件或全部真实问法。

| 运行方式 | CPU 本地离线检索，不调用远端 LLM |
| 时延范围 | 预热后单轮顺序查询，每路径 36 次；不含索引首次构建、网络、模型推理或工单处理 |

先运行原始 CLI 验证可复现性，再通过独立复核脚本保存每条用例的输入、预期章节、实际返回顺序、拒答状态和时延。原仓库代码未修改；复核脚本另存于附件。

### 4.2 指标口径

所有检索质量指标只对 31 条可答用例取逐题平均；5 条拒答用例单独统计。

| 指标 | 计算与解释 |
| --- | --- |
| Hit@3 | 前 3 条是否至少命中一个相关章节；总体为命中题数 / 31 |
| MRR@3 | 首个相关章节排名的倒数；前 3 条未命中则为 0 |
| 标准 P@3 | 前 3 条中相关结果数 / 3；返回不足 3 条时仍除以 3 |
| 实际返回精确率 | 相关结果数 / 实际返回条数；无结果时为 0，用于对照原报告 |
| Recall@3 | 前 3 条命中的不同相关章节数 / 该题标注的相关章节数 |
| NDCG@3 | 二值相关性下的位置折损收益 / 理想排序收益 |
| 正确拒答率 | 应拒答且实际拒答的题数 / 5 |
| 误拒答率 | 可答但实际拒答的题数 / 31 |

原代码名为 `precision_at_k()` 的函数实际除以返回条数，不是固定 K。两条路径分别有 14、15 条可答用例返回不足 3 条，故两个精确率口径差异较大。原报告的 MRR 仅基于截断后的返回列表，本文明确记为 MRR@3。[3]

## 五、实测结果

### 5.1 默认配置总体结果

以下数据来自本次实际执行及独立计算，保留四位小数。

| 指标 | 自然语言 `search()` | 关键词 `retrieve()` |
| --- | ---: | ---: |
| 可答题命中数 | 31/31 | 28/31 |
| Hit@3 | 1.0000 | 0.9032 |
| 首位命中数 | 29/31 | 15/31 |
| MRR@3 | 0.9677 | 0.6774 |
| **标准 P@3：固定除以 3** | **0.3548** | **0.3118** |
| 实际返回精确率：原报告口径 | 0.5323 | 0.4301 |
| Recall@3 | 1.0000 | 0.8871 |
| NDCG@3 | 0.9762 | 0.7233 |
| 正确拒答 | 5/5 | 5/5 |
| 正确拒答率 | 1.0000 | 1.0000 |
| 误拒答 | 0/31 | 0/31 |

按“可答题至少命中一个相关章节、拒答题正确拒答”的通过标准，自然语言路径为 **36/36**，关键词路径为 **33/36**。原报告中的“全部通过”来自仅检查自然语言路径的 `failures` 列表，不适用于双路径整体。[3]

自然语言路径能在该回归集中找到预期依据，但关键词路径仍有 3 条漏检。两条路径均存在非相关结果进入返回列表的情况，故不能把 Hit@3=1.0000 理解为“所有返回内容均正确”。

## 六、失败用例与原因分析

本次补充统计得到关键词路径的 3 条真实漏检：

| 用例 | 原问题 | 实际传入关键词 | 期望章节 | 实际返回章节 |
| --- | --- | --- | --- | --- |
| LS-03 | 大风天气需要加强线路巡检吗 | 异物、处置 | 恶劣天气加强巡检 | 异物分级与处置；影像点复核要求 |
| CB-03 | 乘客躺地上多久算异常 | 车内巡检、处置 | 通道堵塞评估标准 | 车内事件分级与处置；乘务员复核流程 |
| CB-04 | 通道被行李堵住了怎么判断严重程度 | 车内巡检、处置 | 通道堵塞评估标准 | 车内事件分级与处置；乘务员复核流程 |

**输入信息丢失。** 原问题中的天气、时长、堵塞条件没有进入关键词查询。CB-01、CB-02、CB-03、CB-04、CB-06 五题使用相同领域和关键词，却期望不同章节；确定性检索器无法仅凭相同输入区分这些意图。

**相关章节被门槛提前过滤。** 直接计算失败题目标章节得分，结果如下：

| 用例 | 目标章节 TF-IDF 余弦分数 | 当前门槛 | 结果 |
| --- | ---: | ---: | --- |
| LS-03 | 0.0551 | 0.0800 | 被过滤 |
| CB-03 | 0.0581 | 0.0800 | 被过滤 |
| CB-04 | 0.0581 | 0.0800 | 被过滤 |

这三题都返回了其他章节，因此不计入“误拒答”，却仍然属于检索失败。只监控拒答率会漏掉此类“有返回、无正确依据”的问题。

优先改进方向是保留原始问题或补充故障、场景、数值及时间等信息，再在独立数据上联合检查漏检和错误召回。当前证据不足以证明只调大 Top-K 或统一下调门槛即可解决问题。

## 七、参数敏感性实验

在同一提交、知识库和回归集上，另执行 4 组配置；保留现有查询扩展和拒答门槛。它们属于参数敏感性检查，不是与其他检索系统的独立对照实验。

### 7.1 Top-K 变化

固定 α=0.55。

| Top-K | search Hit@K | search MRR@K | retrieve Hit@K | retrieve MRR@K |
| --- | ---: | ---: | ---: | ---: |
| 1 | 0.9355 | 0.9355 | 0.4839 | 0.4839 |
| 3 | 1.0000 | 0.9677 | 0.9032 | 0.6774 |
| 5 | 1.0000 | 0.9677 | 0.9032 | 0.6774 |

Top-3 比 Top-1 覆盖更多相关章节；扩大到 Top-5 未提高命中率。该结果与失败章节在排序前被过滤的分析一致。它支持当前回归集采用 Top-3，但不证明 Top-3 对未来知识库始终最优。

### 7.2 权重变化

固定 Top-K=3。

| α | search Hit@3 | search MRR@3 | retrieve Hit@3 | retrieve MRR@3 |
| --- | ---: | ---: | ---: | ---: |
| 0.00 | 1.0000 | 0.9677 | 0.8387 | 0.6505 |
| 0.55 | 1.0000 | 0.9677 | 0.9032 | 0.6774 |
| 1.00 | 1.0000 | 0.9677 | 0.9032 | 0.7204 |

三组配置下两条路径的正确拒答均为 5/5、误拒答均为 0/31。

自然语言路径在三个 α 下的 36 条返回列表完全一致。原因是其两个计分分支均基于同一组归一化 TF-IDF 向量，一个计算余弦相似度，一个计算点积后再缩放；数学上基本属于同一信号的单调变换。因此这些结果不能证明自然语言路径存在独立双路召回的互补增益。

关键词路径 α=1.00 的 MRR@3 高于默认值，说明本次结果不支持“α=0.55 已是最优配置”。同时，α=0.00 仍保留 TF-IDF 门槛，不应将该行命名为“纯 BM25 基线”。是否更改配置，应由新的独立验证集决定。

## 八、证据边界与后续工作

### 8.1 本次可以确认的结论

1. 当前仓库 RAG 检索模块及评测入口可以离线运行，原报告主要检索数值得到复现。
2. 默认配置下，自然语言路径 31/31 可答题命中，关键词路径 28/31 命中；两路径各有 5/5 拒答题通过。
3. 原报告需修正 Precision 的命名和双路径失败统计，并补充关键词路径漏检。
4. 关键词查询信息不足和门槛过滤是当前失败题的直接问题；单纯扩大 Top-K 未解决这些漏检。

### 8.2 尚不能由这些实验支持的结论

- **真实规程正确性或上线可用性：** 本次数据是内置示例知识，缺少正式原件与业务专家核验。
- **独立泛化性能：** 36 条样本参与过开发调参，拒答题仅 5 条，不能宣称所有库外问题均可可靠拒答。
- **生成答案准确率、忠实度或幻觉率：** 未执行端到端生成评测。
- **优化前后提升幅度：** 仓库记载的历史基线和多轮改进没有在本次逐版本重跑，本文不将其写成本次实测增益。
- **个人历史贡献归属：** 仓库已有评测代码与优化记录不等于本次新增工作；提交比赛材料时，应按实际参与情况署名和描述。

### 8.3 建议的下一轮评测

| 优先级 | 工作 | 验收依据 |
| --- | --- | --- |
| P0 | 修正评测器：双路径失败明细、标准 P@K、真实参数入报告 | 自动摘要与逐题结果一致；当前 Markdown 渲染器把 α 固定写为 0.55，需要同步修正 |
| P0 | 让关键词路径保留场景、时间和故障信息 | 复测 3 条漏检，同时检查新增错误召回与拒答变化 |
| P1 | 新增不参与调参的独立测试集，建议至少 100 条 | 覆盖改写、数值条件、相似章节、领域错误、信息不足与库外问题；建议由两人独立标注并复核分歧 |
| P1 | 引入有来源和版本记录的业务文档 | 标注关联原文、章节及适用条件，专家复核业务内容 |
| P2 | 补充真实 Agent 调用与答案生成评测 | 保存实际工具输入、引用和回答，分别核查路由、检索与生成错误 |

上述为后续计划，不计入本次已完成成果。

## 九、报告结论

RailMind 当前 RAG 模块在小规模内置知识库的开发回归集上具备可复现的检索能力。默认配置下，自然语言检索 Hit@3 为 1.0000、MRR@3 为 0.9677；关键词检索 Hit@3 为 0.9032、MRR@3 为 0.6774。两条路径均通过 5 条拒答测试，但关键词路径仍有 3 条相关章节漏检。

本次评测的主要产出是完成双路径复测、校正精确率口径、补齐失败用例并定位输入信息损失和门槛过滤问题。现阶段应表述为“完成内置知识库上的离线检索验证”，并继续通过独立测试集、正式知识来源和端到端生成评测验证实际业务效果。
